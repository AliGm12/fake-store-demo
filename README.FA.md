## قابلیت ها

- **نمایش محصولات** — نمایش محصولات دریافت‌شده از Fake Store API به صورت grid
- **جستجو** — جستجوی لحظه‌ای محصولات بر اساس عنوان
- **مرتب‌سازی** — امکان مرتب‌سازی لیست محصولات
- **فیلتر بر اساس دسته‌بندی** — فیلتر محصولات بر اساس دسته، همراه با نمایش تعداد محصولات هر دسته
- **Active filter bar** — نمایش فیلترهای اعمال‌شده با امکان حذف تکی هر فیلتر

- **Dark Mode** — امکان تغییر دستی بین حالت روشن 
- **حالت‌های Loading** — نمایش Skeleton برای محصولات، دسته‌بندی‌ها و جزئیات محصول در زمان دریافت اطلاعات
- **مدیریت خطا** — نمایش پیام خطا به کاربر همراه با گزینه تلاش مجدد در صورت شکست درخواست
- **حالت خالی (Empty State)** — نمایش پیام مناسب زمانی که هیچ محصولی با فیلترهای اعمال‌شده مطابقت نداشته باشد
- **طراحی Responsive** — سازگار با موبایل، تبلت و دسکتاپ

## تصمیم‌های فنی و دلایل آن‌ها

-**استفاده از Global Variabels:** به‌جای نوشتن مستقیم کد رنگ (hex) در هر کامپوننت، رنگ‌های تکرارشونده در قالب Global Variables در :root تعریف شدند تا مدیریت رنگ های تکرار شونده راحت تر شود.

-**پیاده سازی دارک مود:** با استفاده از کامپوزیبل سفارشی useColorMode حالت دارک مود بابت تجبره کاربری بهتر پیاده سازی شد.

-**استفاده از Nuxt UI:** برای کامپوننت های مشترک مثل Skeleton, Alert, Empty State از کتابخانه Nuxt UI استفاده شد تا از پیاده سازی از صفر جلوگیری شود و کاهش زمان توسعه را نیز داشته باشیم.

- **استفاده از Tailwind CSS:** برای استایل دهی پروژه از Tailwind CSS استفاده شد، چون نیاز به نوشتن فایل های CSS جداگانه نیست و مدیریت نامگذاری کلاس ها دیگر لازم نیست. همچنین بابت ریسپانسیو سازی و پیاده سازی دارک مود گزینه به مراتب بهتری می‌باشد.

- **استفاده از TypeScript:** برای افزایش خوانای، جلوگیری از خطاهای رایج در زمان توسعه از تایپ اسکریپت بجای جاوااسکریپت خام استفاده شد.

 **قرار دادن آیکون‌ها در یک فایل مرکزی (`components/icons/index.ts`):**  به‌جای import مستقیم هر آیکون از کتابخانه‌های `lucide-vue-next` و `vue3-simple-icons` در تک‌تک کامپوننت‌ها، تمام آیکون‌های مورد استفاده در پروژه در یک فایل گلوبال export شدند. از دلایل آن میشه به مدیریت آیکون ها در صورت تغییر نام یا تغییر پکیج و خوانایی بالاتر اشاره داشت.

- **جداسازی منطق در سه Composable مستقل:** به‌جای قرار دادن تمام منطق data fetching و فیلتر کردن در یک فایل یا داخل کامپوننت ، این منطق بر اساس Single Responsibility به سه بخش جدا تقسیم شد:
  - **`useProducts`:** مسئول دریافت لیست محصولات از Fake Store API.
  - **`useCategories`:** مسئول دریافت دسته‌بندی‌ها.
  - **`useProductFilters`:** مسئول مدیریت state فیلترها (جستجو، مرتب‌سازی، دسته‌بندی انتخاب‌شده) و اعمال آن‌ها روی لیست محصولات.

علت این پیاده سازی از این روش این است که هر کامپوزیبل به تنهایی قابل تست و نگه داری هست و هر کدام منطق مجزا به خود را دارند که باعث افزایش خوانایی می‌شود 

بطور کل سعی شد تمامی اصول SOLID به بهترین نحو رعایت شود.
